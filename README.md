# QZZ 公共测试平台

供公司内网使用的游戏测试协作平台。Windows 主机运行服务，同事通过 Windows 或 Mac 浏览器访问。首版包含测试用例库、当前缺陷、AI 用例生成和测试工具云盘；用例、缺陷和文件变更会实时同步到已登录的页面。

## 启动

主机需要 Node.js 22 或更新版本。首次使用，在项目根目录运行：

```powershell
npm install
npm run build
npm start
```

服务默认监听所有网卡的 `3210` 端口。主机可访问 `http://localhost:3210`，同一内网中能连通主机的同事访问 `http://主机内网IP:3210`。按 `Ctrl+C` 可停止命令行启动的服务。Windows 可视化控制器及其一键启动、停止和登录后自启的用法见 `desktop/README.md`。

首次启动会在 `data/initial-admin.txt` 写入随机管理员账号和密码。请在主机上读取并妥善保管；管理员首次成功登录后，这个明文文件会被删除。管理员可在网页右上角的账号管理入口创建成员账号。不要让全组共用管理员账号。

**开机并联网不等于服务已经启动。** 服务必须保持运行，主机不能休眠或断网；Windows 防火墙需要允许该端口的内网入站访问。跨网段或隔离 VLAN 还需公司网络策略允许。自动启动功能在 Windows 用户登录后触发，不保证尚未登录时可用。请先与公司 IT 确认内网开放端口与测试资料的存放政策。

## 数据与配置

数据库、上传文件及首次口令默认保存在项目根目录的 `data/`，不会加入 Git。迁移主机或备份时，先停止服务再复制整个 `data/` 目录。代码更新不应覆盖该目录。可用 `QZZ_DATA_DIR` 指定其他位置，用 `PORT` 和 `MAX_UPLOAD_MB` 调整端口及单文件上传上限（默认 100 MB）。

AI 用例生成默认不可用，不会假装生成结果。只有管理员明确配置 `AI_API_KEY`、`AI_MODEL`（以及按需配置 `AI_BASE_URL`）后，需求文本才会发送给该 AI 服务。将公司的需求文档发送给外部服务前，请先确认公司数据合规要求。生成结果是待审核草稿，不应直接视为已验证用例。

内网 HTTP 流量默认不加密；如需在不可信网络或跨地点访问，应配置 HTTPS、网络访问控制与更可靠的持续运行主机。首版的账号管理支持创建成员，不包含密码重置、账号停用与细分权限。

## 开发与验证

```powershell
npm run dev:server
npm run dev:client
npm run build
npm test -w qzz-platform-server
```

开发界面由 Vite 提供，API 代理到本机 `3210` 端口；正式使用时由服务端提供构建后的网页。`server/README.md` 记录接口和环境变量细节。
