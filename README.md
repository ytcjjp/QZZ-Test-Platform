# QZZ 公共测试平台

Git 仓库名称：QZZ-Test-Platform。

供公司内网使用的游戏测试协作平台。Windows 主机运行服务，同事通过 Windows 或 Mac 浏览器访问。首版包含测试用例库、当前缺陷、AI 用例生成和测试工具云盘；用例、缺陷和文件变更会实时同步到已登录的页面。

## 项目组

点击“测试用例库”或“当前缺陷”后，必须先选择项目组，才会加载该组的记录。两处共用同一套项目组；进入后可通过“切换项目组”返回选择界面。每次从侧边栏进入这两个模块都会先显示项目组选择。

管理员可新增项目组、重命名、上传图标和删除项目组。删除时须输入项目名称确认，关联数据保留，可从“已删除项目组”完整恢复。普通成员按已分配的模块权限选择项目组、查看或编辑记录，不能管理项目组。项目组名称不能重复。图标支持 PNG、JPEG、WebP、GIF，单张最大 2 MB；服务端验证图片后统一处理为静态 WebP。

旧版本的用例和缺陷会在首次更新时迁入“默认项目组”，记录内容和版本号保持不变。项目组改名不会改变记录归属。AI 生成的用例保存前也需要明确选择目标项目组。

## 用例集与缺陷

测试用例库以用例集管理思维导图。新建时自定义名称，初始只有一个中心主题；进入后可新增、编辑、删除主题，撤销、重做、缩放并保存。多人编辑同一用例集时检查版本，冲突不会覆盖本地未保存内容，可载入最新版本或另存为新的用例集。离开未保存的编辑会要求确认。

用例集可导入、导出 `.xmind` 和 UTF-8 `.md`；多个用例集导出 XMind 时为多个画布，导出 Markdown 时打包为 ZIP。支持现代 XMind JSON 和传统 XML 文件的主题树。主题文本和层级参与转换，原文件的布局、附件、样式和特殊图形不保证保留。旧版平铺用例会自动转换为包含原字段的主题树，原记录信息仍保留。

用例集和缺陷列表均可多选、全选和批量删除。缺陷状态可以在列表中直接修改，也可选择多条后统一修改。批量操作会校验每条记录的项目和版本，任意记录冲突时整批拒绝，防止部分成功造成混淆。

## 从策划案生成用例

AI 入口接收拖放或选择的 Word、PDF、Markdown、文本文件，也接收飞书云文档链接。文档解析后可预览正文，再发起生成；不再提供手动需求输入。扫描图片型 PDF 需要先转为可提取文本的文档。

生成规则来自 `game-prd-testcases`，组织为“主流程、UI、异常与边界、受影响模块”，每条用例包括“前置条件、执行步骤、预期结果”。不明确的业务规则先列出待确认问题，补充答案后重新生成。审核后可将整份思维导图保存到选定项目组。

读取飞书文档需管理员在 AI 页配置飞书应用，并为应用开放目标文档的读取权限；也可以设置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`。应用密钥在本地加密保存，不加入 Git。飞书链接访问受实际文档和应用权限约束。

## 启动

主机需要 Node.js 22 或更新版本。首次使用，在项目根目录运行：

```powershell
npm install
npm run build
npm start
```

服务默认监听所有网卡的 `3210` 端口。主机可访问 `http://localhost:3210`，同一内网中能连通主机的同事访问 `http://主机内网IP:3210`。按 `Ctrl+C` 可停止命令行启动的服务。Windows 可视化控制器及其一键启动、停止和登录后自启的用法见 `desktop/README.md`。

首次启动会在 `data/initial-admin.txt` 写入随机管理员账号和密码。请在主机上读取并妥善保管；管理员首次成功登录后，这个明文文件会被删除。登录页支持注册成员账号和自定义密码，注册时不能自行取得管理员权限。密码长度为 6-200 个字符。

管理员在网页右上角的账号管理入口创建账号、停用账号、调整角色和四个工作区的查看/编辑权限，也可以重新设置密码。普通成员只能管理自己的密码。账号菜单提供修改密码入口，修改时需要验证原密码。

登录时可选择记住账号和密码；只在个人信任的浏览器中启用。取消勾选会清除平台保存的登录信息。记住登录的有效期为 30 天；未勾选时会话不写入持久 Cookie。

**开机并联网不等于服务已经启动。** 服务必须保持运行，主机不能休眠或断网；Windows 防火墙需要允许该端口的内网入站访问。跨网段或隔离 VLAN 还需公司网络策略允许。自动启动功能在 Windows 用户登录后触发，不保证尚未登录时可用。请先与公司 IT 确认内网开放端口与测试资料的存放政策。

## 数据与配置

数据库、上传文件、账号密码加密密钥及首次口令默认保存在项目根目录的 `data/`，不会加入 Git。迁移主机或备份时，先停止服务再复制整个 `data/` 目录；密码加密密钥必须与数据库一起保留。代码更新不应覆盖该目录。可用 `QZZ_DATA_DIR` 指定其他位置，用 `PORT` 和 `MAX_UPLOAD_MB` 调整端口及单文件上传上限（默认 100 MB）。

为支持管理员查看密码，新创建或新修改的密码同时保存登录哈希和可解密的加密副本。查看时需要再次验证管理员密码，查看和重设操作会记录审计日志。旧版本只有哈希的账号需要先重设密码，之后才可查看。数据库与本地密钥同时泄露可能导致密码被还原，因此请限制服务器目录和备份的访问权限。平台不会把密码写入普通账号列表或操作日志。

AI 用例生成默认不可用，不会假装生成结果。只有管理员明确配置 `AI_API_KEY`、`AI_MODEL`（以及按需配置 `AI_BASE_URL`）后，需求文本才会发送给该 AI 服务。将公司的需求文档发送给外部服务前，请先确认公司数据合规要求。生成结果是待审核草稿，不应直接视为已验证用例。

内网 HTTP 流量默认不加密；如需在不可信网络或跨地点访问，应配置 HTTPS、网络访问控制与更可靠的持续运行主机。

## 开发与验证

```powershell
npm run dev:server
npm run dev:client
npm run build
npm test -w qzz-platform-server
```

开发界面由 Vite 提供，API 代理到本机 `3210` 端口；正式使用时由服务端提供构建后的网页。`server/README.md` 记录接口和环境变量细节。
