## 典型流程

1. 进入“需求管理”，先选项目组，再新建需求。正文与附件至少提供一项；状态可选草稿、已确认、已归档，优先级为 P0-P3。
2. 核对导入结果。PDF 可预览原件；Word 可查看提取正文和嵌图并下载原件。图片保留原件预览，AI 使用实际图片数据；解析失败时会提示补正文或重新导入。
3. 按需要完成需求分析和测试计划。分析结果可在线修改；人员、人天、日期、环境等没有依据时，应保留“待确认”，由测试人员确认后写入。
4. 将已有规则、技术说明和历史问题导入“项目知识库”，查看分块并试检索。调整参数后重建索引，再用于 AI 引用。
5. 在“AI 用例生成”选择需求和知识库，使用快速或分步模式。分步模式先确认测试点；用例确认完成后再写入测试用例库。

需求分析的固定三段为：功能清单、界面描述、待澄清项。测试计划的固定八章为：目标与范围、策略与优先级、环境与数据、人力与人天、进度与里程碑、进入标准/退出标准、风险与应对、交付物。

用例沿用点点消项目的技能结构：主流程、UI、异常与边界、受影响模块。每条用例包含前置条件、一句话执行步骤和可观察的预期结果。规则不明确时先回答待澄清问题；也可明确选择只覆盖已确认规则，依赖未知规则的用例不能被悄悄补入。

## 知识检索与评审

知识库采用可验证的本地词法检索，不依赖外部向量数据库。文档文本按固定窗口或 Markdown 标题分段切块；默认长度 400、重叠 80，支持精细、标准、标题三个预设，也可自行调整。块长为 100-4000，重叠必须小于块长，单文档最多 10000 个分块。调整设置后会提示索引待更新；试检索展示实际命中的文本及来源。

AI 只引用本次提供的资料。没有命中知识分块、图片不可读取或源码上下文不足时，会显示相应提示，不会把候选文件路径当作已读源码。正文编辑后，以当前正文为准；原始附件和原始提取文字仍保留供核对，旧规则不会因保留附件而重新混入检索正文。

需求分析、测试计划以及这两类草稿的对话修订不采集游戏源码，避免混入与当前策划无关的实现。测试点和用例任务才按需要使用主机只读提取的相关代码；生成进程不能自行运行系统命令。Codex 使用隔离目录并禁用插件初始化，网关请求和流恢复分别配置有限重试，取消与总超时仍然有效。

评审维度为覆盖完整性、正确性、冗余去重、边界与异常、步骤清晰度、优先级合理性、前置/数据完整性、需求追溯。报告是同轮 AI 自评，不代表用例已经执行或通过人工评审；人工编辑用例后应重新核对评审结果。

## 真实限制

| 范围 | 当前行为 |
| --- | --- |
| 来源原件上传 | 需求、知识库及策划来源上传不设固定 20 MB 文件上限；原件保存与单轮模型读取预算分开。原有工具云盘、项目图标、用例集导入仍遵循各自设置。 |
| 文本解析与单轮 AI 资料 | 自动提取的正文最多 10 万字符，单轮需求资料也最多 10 万字符；超限需拆分。PDF 自动解析最多 300 页，Word 压缩包展开预算为 64 MiB。解析失败不冒充成功，需求/知识库原件仍可下载并补正文。 |
| 模型图片输入 | 每轮最多 64 张，模型输入图片合计最多 64 MiB，单图安全解码上限 4000 万像素。超限明确拒绝本轮生成，不截取前几张冒充完整分析；这不等于原件上传限制。 |
| 图片和 DOCX 嵌图 | 保留原件及嵌图，生成可验证的 PNG 供 AI 视觉输入；不把图片文件名当作图片内容。DOCX 超出单轮媒体预算时可查看原件，但须拆分后再 AI 分析。 |
| 扫描 PDF | 当前没有 OCR，也未自动把 PDF 全部页面转换为视觉输入。无可读文字时需补充截图或正文，不能据空白提取结果生成完整用例。 |
| 飞书 | 需先配置应用和授权；当前接口读取文字，图片、布局需另补附件，不能视为已完整读取。 |
| 对话与质量 | 对话修订使用当前完整草稿；草稿和历史有容量预算，过长需另开一轮。生成质量仍由测试人员结合需求和资料确认。 |

## 权限与数据

新增 `requirements`、`knowledge` 两个模块，各有查看和写入权限。需求分析结果和测试计划使用需求管理权限，知识库使用知识库权限；AI 任务另外需要 AI 写权限，引用知识库需要知识库查看权限，生成及写入用例需要用例库写权限。管理员可在账号管理中关闭成员权限。

旧账号没有这两个权限字段时，按原平台规则兼容为可查看、可写入；不会改写旧账号已有模块权限。管理员始终有全部权限。业务接口和 WebSocket 在服务端检查权限，项目归属同样在服务端验证。

需求、测试计划、知识库和知识文档持久保存到原有 SQLite 数据库。修改使用 `revision` 防止覆盖他人内容；冲突保留当前草稿并要求刷新。删除需求后解除其用例关联，保留用例导图和已有测试计划；需求及来源原件采用逻辑删除保留历史资料。

从某条需求进入用例库后，新建和导入会沿用该需求关联，另存副本保留原关联；服务端仍验证需求查看权限和所属项目。工具云盘新上传文件修复 UTF-8 中文名称识别，下载保持原始文件内容。

备份应包含整个 `data/`，尤其是 `platform.db`、原 `password-key`、`workspace-documents/` 下的来源原件和视觉派生图、原有 `uploads/`、`project-icons/`、AI/飞书本机配置。数据库应停服备份或使用 SQLite 在线备份，不能仅复制运行中的主 DB 而遗漏 WAL。不要把数据、密钥或备份提交到 Git。

## 飞书授权与生成错误

管理员可从“需求管理”页头或来源导入弹窗打开“飞书文档连接”，AI 来源导入也复用这一配置组件。已保存 Secret 不回显；同一 App ID 留空保留原凭据，更换 App ID 需填写新 Secret。QZZ 管理员身份不等于飞书企业审批或文档授权：还需发布应用、开通相应文档读取权限，并让应用可访问目标文档。具体范围以飞书官方[纯文本接口说明](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/raw_content)及[云文档权限帮助](https://www.feishu.cn/hc/zh-CN/articles/360044508113-%E4%BA%91%E6%96%87%E6%A1%A3%E6%9D%83%E9%99%90%E5%B8%B8%E8%A7%81%E9%97%AE%E9%A2%98)为准。本次未配置真实飞书租户，不能据 mock 导入通过宣称企业授权已验证；也可下载 Word/PDF 后导入。

AI 失败会区分认证、模型或接口配置、结构化协议、上下文超限、限流、连接/流中断、超时和本机运行问题。受控提示可附诊断编号，管理员据此检查 `data/codex-diagnostics/`；最多保留 50 条白名单摘要，含耗时、错误分类和输入数量等，不保存需求原文、提示词、密钥或原始进程日志。未知退出仍有通用提示，诊断编号不代表已经确定根因。网关请求重试参数为 2、流恢复参数为 1，不会无限重试。

后端验证：在项目根目录运行 `npm test --prefix server`。测试覆盖模块权限、跨项目隔离、修订冲突、原件下载、DOCX 嵌图、22/60 张图片证据、超限拒绝、分块检索、索引重建、需求关联、实时事件过滤和旧数据重启保留。

网页应核对需求创建/编辑、三段分析、八章计划、知识库配置与试检索、快速/分步生成、测试点编辑、列表/宫格预览、评审、正式写入和重开导图。自动化模型测试使用可控 mock；真实网关调用的质量及资料解读应单独核对，不因界面或单元测试通过而宣称全部真实文档已验收。
