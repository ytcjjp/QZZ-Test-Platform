| 需求筛选下新建、导入或复制用例后从当前列表消失 | 新建和导入继承当前需求关联；复制保留原关联。导入 API 新增可选 `requirementId`，服务端校验需求查看权限、项目归属及未删除状态。跨项目和无权限导入分别被拒绝。 |
| 需求管理页缺少管理员飞书配置入口 | `RequirementsPage` 接收管理员标记，页头、来源导入弹窗及相关错误提示提供共享配置入口；普通成员入口隐藏，服务端配置接口仍独立验证管理员身份。 |
| Codex 非正常退出难以定位 | 根据终端模型错误区分认证、模型、接口、结构协议、上下文超限、限流、连接/流中断、超时及运行环境；页面给受控提示和诊断编号，保留通用未知退出兜底。不会把插件启动警告里的状态码直接当作模型失败原因。 |
| 需求分析携带无关游戏源码 | `analysis`、`plan` 及对应修订只使用本次需求、图片和选定知识库；测试点/用例任务才按需附只读采集的相关源码。没有提供的源码不会被声明为已读取。 |

Codex 运行继续使用隔离目录、只读沙箱和禁用系统命令的资料分析方式；新增禁用插件，避免额外初始化干扰。网关请求重试参数为 `request_max_retries=2`、流恢复参数为 `stream_max_retries=1`，受任务总超时和取消约束，不会无限重试。

失败诊断位于数据目录的 `codex-diagnostics/`，最多保留 50 条。只保存时间、模型标识、错误分类、HTTP/退出状态、耗时、输入字符数、图片数，以及符合白名单的请求编号；不保存提示词、需求原文、图片内容、密钥、网关地址、环境变量或 stdout/stderr 原文。临时任务材料与这些摘要诊断分开管理。
